نظام ذكاء المشتريات والمخزون — مركز التحكم

يحلل المبيعات والمخزون الحالي (من كويريات SAP الملصوقة يدوياً) ويقترح لكل صنف: هل يُشترى الآن، كم الكمية، ومتى — مع شرح كامل لكل توصية.
القاعدة: Reorder Point = (متوسط الطلب اليومي × مدة التوريد) + مخزون الأمان
الكمية المقترحة: الاحتياج بعد تصحيح المخزون القادم، مقيّدة بـ MOQ ومضاعف الطلب والصلاحية
1 كويري الأصناف (إلزامي)
الصق نتيجة كويري الأصناف (رمز الصنف + الاسم إلزاميان). يُنشئ صفاً تلقائياً لكل صنف في جدول البارامترات أسفل الصفحة. SELECT T0."ItemCode" AS "رمز الصنف", T0."ItemName" AS "اسم الصنف" FROM OITM T0 WHERE T0."validFor"='Y'
🗂 استيراد كشف كامل الأصناف من SAP (يضيف الناقص بس — ما بيلمس أصناف موجودة)
لصق تصدير "Items" الكامل من SAP B1 مباشرة (نفس أعمدة "Item No." / "Item Description") أو أي كويري فيها هالعمودين. بيضيف بس الأصناف يلي مش موجودة أصلاً بجدول البارامترات — ما بيغيّر اسم أي صنف موجود مسبقاً حتى لو مختلف.
2 كويري المبيعات التاريخية (إلزامي)
كل ما زاد المدى الزمني كل ما كان التوقع أدق. المستودع والعميل والمبلغ أعمدة اختيارية — بدونها بيشتغل التوقع عادي، بس تقرير "الأصناف" (تفصيل حسب العميل والمبالغ) بيحتاجهم. رمز العميل اختياري كمان — لو موجود، بيُستخدم لربط اسم موثوق من بيانات العملاء المستوردة (تحت) بدل الاعتماد على اسم الفاتورة بس. عند تشغيل الكويري بـ SAP رح تُطلب منك تاريخ البداية والنهاية. SELECT T1."ItemCode" AS "رمز الصنف", T0."DocDate" AS "التاريخ", T1."Quantity" AS "الكمية", T1."WhsCode" AS "المستودع", T0."CardCode" AS "رمز العميل", T0."CardName" AS "العميل", T1."LineTotal" AS "المبلغ" FROM OINV T0 INNER JOIN INV1 T1 ON T0."DocEntry"=T1."DocEntry" WHERE T0."DocDate" BETWEEN [%0] AND [%1] ORDER BY T1."ItemCode", T0."DocDate"
3 كويري المخزون الحالي (إلزامي)
الرصيد الحالي إلزامي. الوارد/تحت الطلب واسم المستودع اختياريان (بدون اسم المستودع، بيتعرض رمزه بس بتفصيل الرصيد). SELECT T0."ItemCode" AS "رمز الصنف", T0."WhsCode" AS "المستودع", T1."WhsName" AS "اسم المستودع", T0."OnHand" AS "الرصيد الحالي", T0."OnOrder" AS "تحت الطلب" FROM OITW T0 LEFT JOIN OWHS T1 ON T0."WhsCode"=T1."WhsCode"
4 تاريخ أوامر الشراء (اختياري — لتقدير مدة التوريد الفعلية)
بدون هذا الكويري، تُستخدم مدة التوريد التعاقدية اليدوية (بجدول البارامترات) مع افتراض تذبذب 20٪ حوله. عندكم الاستلام ما بينربط رسمياً بأمر الشراء (Copy From)، فبدل ما نحتاج ربط مباشر بقاعدة البيانات، هالكويري بتجيب بس تاريخ كل أمر شراء، والشاشة بتطابقه تلقائياً مع أقرب استلام فعلي بعده لنفس الصنف والمورد (من كويري رقم 6) لتقدير مدة التوريد — بدون الحاجة لأي ربط SQL معقّد. SELECT T1."ItemCode" AS "رمز الصنف", T0."CardCode" AS "المورد", T0."DocDate" AS "تاريخ الطلب", T1."Quantity" AS "الكمية" FROM OPOR T0 INNER JOIN POR1 T1 ON T0."DocEntry"=T1."DocEntry" WHERE T0."DocDate" BETWEEN [%0] AND [%1] ORDER BY T1."ItemCode", T0."DocDate"
5 كويري بارامترات الشراء — Lead Time / MOQ / مضاعف الطلب (اختياري — بديل التعبئة اليدوية)
Lead Time وMOQ ومضاعف الطلب حقول قياسية بـ SAP (تبويب Planning Data ببطاقة الصنف) — الكويري تحت جاهز ومجرَّب. الصلاحية وحد أدنى صلاحية عند الاستلام عادةً مش موجودين، تُدخَلان يدوياً بجدول البارامترات. SELECT T0."ItemCode" AS "رمز الصنف", T0."U_U_ST_V_NAME" AS "المورد", T0."LeadTime" AS "Lead Time تعاقدي (يوم)", T0."MinOrdrQty" AS "MOQ", T0."OrdrMulti" AS "مضاعف الطلب" FROM OITM T0 WHERE T0."validFor"='Y'
⚠ Lead Time = صفر بـ SAP يعني غالباً "غير محدَّد" مش "توصيل فوري" — الشاشة تتجاهله تلقائياً وتُبقي الصنف بحالة بيانات ناقصة بدل ما تاخذ رقماً غير واقعي.
6 تاريخ استلام البضاعة (GRPO) — لتحليل حمولة الشحنة المعتادة لكل مورد (اختياري)
نستخدم استلام البضاعة (GRPO) لا فاتورة الشراء، لأنه بيعكس فعلياً شو وصل سوا بنفس الشحنة (والتاريخ فيه دقيق، بعكس تاريخ إدخال الفاتورة). كل ما زاد المدى الزمني (سنتين-ثلاثة) كل ما كان التحليل أدق. رقم المستند إلزامي — هو اللي بيربط الأصناف يلي وصلت سوا بنفس الشحنة. عمود السعر اختياري — هاد سعر المنشأ (سعر الفاتورة وقت الاستلام، بدون شحن/جمارك/مصاريف)، مش الكلفة الفعلية النهائية. بتقدر تشوف بتقرير الأصناف آخر سعر منشأ لكل صنف مقارنة بالي قبله، وآخر 5 أسعار جنب بعض. للكلفة الفعلية بعد اللاندد كوست شوف كويري رقم 8 تحت. SELECT T1."ItemCode" AS "رمز الصنف", T0."CardCode" AS "المورد", T0."DocEntry" AS "رقم الفاتورة", T0."DocDate" AS "تاريخ الفاتورة", T1."Quantity" AS "الكمية", T1."Price" AS "السعر" FROM OPDN T0 INNER JOIN PDN1 T1 ON T0."DocEntry"=T1."DocEntry" WHERE T0."DocDate" >= ADD_YEARS(CURRENT_DATE, -3) ORDER BY T0."CardCode", T0."DocEntry"
7 طلبات الشراء المفتوحة (Purchase Orders) — بضاعة بالطريق (اختياري بس مهم)
بدون هالكويري، الكمية "تحت الطلب" من كويري المخزون (رقم 3) بتُستخدَم كرقم إجمالي بدون تاريخ وصول — يعني ما فينا نعرف بالضبط الشحنة رح توصل قبل أو بعد الانقطاع. بهالكويري، تاريخ الانقطاع المتوقع بيصير محسوب يوم بيوم مع أخذ موعد كل شحنة بعين الاعتبار (مش بس الكمية). SELECT T1."ItemCode" AS "رمز الصنف", T1."OpenQty" AS "الكمية", T1."ShipDate" AS "تاريخ الوصول المتوقع", T0."CardName" AS "المورد" FROM OPOR T0 INNER JOIN POR1 T1 ON T0."DocEntry"=T1."DocEntry" WHERE T0."DocStatus"='O' AND T1."LineStatus"='O'
⚠ تحقق من اسم عمود "الكمية المتبقية غير المستلمة" و"تاريخ الوصول" عندكم (ممكن يختلف الاسم) قبل ما تشغّل الكويري — بنفس أسلوب فحص TABLE_COLUMNS يلي استخدمناه قبل.
8 مستندات اللاندد كوست (Landed Cost) — الكلفة الفعلية النهائية لكل شحنة/باتش (اختياري)
سعر كويري رقم 6 هو سعر المنشأ (سعر الفاتورة وقت الاستلام) بس — ما بيشمل الشحن والجمارك والمصاريف. هالكويري بيجيب مستندات اللاندد كوست نفسها (OIPF/IPF1) مربوطة بمستند الأساس (GRPO/فاتورة). ملاحظة مهمة: عمود "Final Unit Cost" بالكويري هو فعلياً الكلفة الإضافية للوحدة بس (شحن/جمارك/مصاريف)، مش شامل سعر المنشأ — الشاشة بتحسب الكلفة النهائية الحقيقية تلقائياً = سعر المنشأ (Base Doc. Price) + هالكلفة الإضافية، وبتحسب نسبة الزيادة الصحيحة بنفسها (تجاهلي عمود "Increase %" بالكويري لأنه طالع سالب وغلط). الفلتر بالأسفل بياخذ آخر لاندد كوست بالسلسلة بس (لو انعمل أكتر من مستند لاندد كوست متتالي لنفس السطر). عند تشغيل الكويري بـ SAP رح تُطلب منك تاريخ البداية والنهاية. SELECT /* Landed Cost Header */ T0."DocNum" AS "Landed Cost No", T0."DocDate" AS "Landed Cost Date", T0."Ref1" AS "Reference 1", T0."CardCode" AS "Vendor Code", T0."SuppName" AS "Vendor Name", /* Base Document */ CASE WHEN T1."BaseType" = 20 THEN 'GRPO' WHEN T1."BaseType" = 18 THEN 'A/P Invoice' WHEN T1."BaseType" = 69 THEN 'Landed Cost' ELSE CAST(T1."BaseType" AS NVARCHAR(20)) END AS "Base Document Type", T1."BaseEntry" AS "Base Document Internal ID", T1."BaseRowNum" AS "Base Row Number", /* Item Details */ T1."ItemCode" AS "Item Code", T1."Dscription" AS "Item Description", T1."WhsCode" AS "Warehouse", T1."Quantity" AS "Quantity", T1."UnitCode" AS "UoM", T1."DistNumber" AS "Batch Number", /* Purchase Cost */ T1."Currency" AS "Currency", T1."Rate" AS "Exchange Rate", T1."PriceAtWH" AS "Base Doc. Price", (T1."PriceAtWH" * T1."Quantity") AS "Base Doc. Value", /* Landed Cost Details */ T1."FobValue" AS "FOB Value", T1."FobValCurr" AS "FOB Currency", T1."Custom" AS "Customs", T1."Cost" AS "Additional Cost", T1."TtlExpndLC" AS "Landed Cost Amount", /* Final Cost */ T1."TtlCostLC" AS "Total", CASE WHEN T1."Quantity" <> 0 THEN T1."TtlCostLC" / T1."Quantity" ELSE 0 END AS "Final Unit Cost", /* Increase Analysis */ CASE WHEN T1."Quantity" <> 0 THEN (T1."TtlCostLC" / T1."Quantity") - T1."PriceAtWH" ELSE 0 END AS "Landed Cost Increase Per Unit", CASE WHEN T1."PriceAtWH" <> 0 THEN (((T1."TtlCostLC" / T1."Quantity") - T1."PriceAtWH") / T1."PriceAtWH") * 100 ELSE 0 END AS "Increase %", /* Tax */ T1."VatGroup" AS "VAT Group", T1."VatPrcnt" AS "VAT %" FROM OIPF T0 INNER JOIN IPF1 T1 ON T0."DocEntry" = T1."DocEntry" /* Take Last Landed Cost in Chain */ WHERE NOT EXISTS ( SELECT 1 FROM IPF1 N1 WHERE N1."BaseType" = 69 AND N1."BaseEntry" = T0."DocEntry" AND N1."ItemCode" = T1."ItemCode" ) AND T0."DocDate" BETWEEN '[%0]' AND '[%1]' ORDER BY T0."DocDate", T0."DocNum", T1."ItemCode";
⚠ ممكن يكون حجمها كبير حسب المدى الزمني المختار — فضّل ترفع ملف بدل اللصق المباشر لو النتيجة كبيرة.
🗂 استيراد بيانات العملاء (رمز/اسم، لربط تفصيل المبيعات حسب العميل)
لصق تصدير "Customers" الكامل من SAP B1 مباشرة (نفس أعمدة "BP Code" / "BP Name") أو كويري SELECT "CardCode" AS "رمز العميل", "CardName" AS "اسم العميل" FROM OCRD WHERE "CardType"='C'. يُستخدم لعرض اسم موثوق بتفصيل مبيعات العميل بالتقرير حتى لو تغيّر اسم العميل بفاتورة قديمة. إضافة فقط — ما بيغيّر اسم موجود مسبقاً.

أداء الموردين ونوع العلاقة التجارية

مدة التوريد والتأخير محسوبة من كويري "تاريخ الطلب والاستلام الفعلي" (رقم 4) مجمَّعة على كل أصناف نفس المورد سوا — أدق إحصائياً من حساب كل صنف لحاله. رتّب الجدول تلقائياً حسب أطول تأخير مسجَّل.
نوع العلاقة: "عادي" = القرار حسب معدل الطلب والتغطية كالعادة · "عقد سنوي/موسمي" و"تارجيت وتعويض" = لا تُعرَض توصية "أوقف الشراء" تلقائياً حتى لو زاد المخزون — القرار يرجع لك حسب حالة العقد.
📋 استيراد أسماء الموردين الحقيقية (لو عمود "المورد" عندك بيطلع رمز متل V000002 بدل الاسم)
عمود "المورد" بكويري البارامترات بيجيب حقل حر بـ SAP (UDF) وممكن يكون فيه أحياناً رمز المورد بدل اسمه. الصق هنا قائمة رمز المورد واسمه (من جدول الموردين OCRD مثلاً)، وبتنعرض الأسماء بدل الرموز بكل الشاشة (تقرير الأصناف، تبويب الموردون) — بدون ما تغيّر شي بربط البيانات نفسه. SELECT "CardCode" AS "رمز المورد", "CardName" AS "اسم المورد" FROM OCRD WHERE "CardType"='S'
