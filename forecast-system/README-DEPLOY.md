# نشر النظام على Railway

## 1) إنشاء المشروع على Railway
1. سجّل دخول على railway.app بحسابك.
2. **New Project → Deploy from GitHub repo** → اختر هذا المستودع (`moh-abdalqader`).
3. من إعدادات الخدمة (Settings → Service) اضبط **Root Directory** على `forecast-system` (لأن الباك-إند موجود بمجلد فرعي وليس بجذر المستودع).

## 2) إضافة قاعدة بيانات PostgreSQL
1. داخل نفس مشروع Railway: **New → Database → Add PostgreSQL**.
2. Railway يربطها تلقائياً ويوفر متغيّر `DATABASE_URL` لخدمة التطبيق (تأكد أنه ظاهر في تبويب Variables لخدمة الـ Backend، أحياناً تحتاج تربطه يدوياً بالضغط على "Add Variable Reference").

## 3) متغيرات البيئة (Variables) لخدمة الـ Backend
أضف من تبويب **Variables**:

| المتغير | القيمة |
|---|---|
| `JWT_SECRET` | نص عشوائي طويل وسري (مثلاً 40+ حرف) — لا تشاركه مع أحد |
| `ADMIN_USERNAME` | اسم مستخدم Admin الأول (مثلاً `admin`) |
| `ADMIN_PASSWORD` | كلمة مرور قوية لحساب Admin الأول |
| `NODE_ENV` | `production` |

`DATABASE_URL` و `PORT` يوفرهما Railway تلقائياً — لا تضبطهما يدوياً.

> حساب الـ Admin يُنشأ تلقائياً عند أول تشغيل فقط إذا لم يوجد أي مستخدم بقاعدة البيانات بعد. بعدها أنشئ باقي حسابات المندوبين (حتى 5) من شاشة "👤 المستخدمون" داخل النظام نفسه.

## 4) أول نشر (Deploy)
Railway يكتشف تلقائياً أنه مشروع Node.js (عبر `package.json`) وينفّذ `npm install` ثم `npm start`. لا حاجة لأي إعداد إضافي.

## 5) تغذية البيانات عبر GitHub Desktop (سير العمل اليومي)
1. جهّز ملف **CSV أو Text** بنفس ترتيب الأعمدة (راجع تبويب "🔄 استيراد ومزامنة" داخل النظام، أو README الرئيسي بالمستودع).
   - إذا الملف عندك Excel، احفظه بصيغة **CSV UTF-8** أولاً (Excel: Save As → CSV UTF-8).
2. ضعه داخل:
   - `forecast-system/data/incoming/withdrawals/` لملفات المسحوبات.
   - `forecast-system/data/incoming/stock/` لملفات الرصيد الافتتاحي/التوريدات (اختياري).
3. من GitHub Desktop: **Commit** ثم **Push origin**.
4. Railway يكتشف الـ Push تلقائياً ويعيد نشر الخدمة؛ عند بدء التشغيل يفحص المجلدين ويستورد أي ملف جديد فقط (لا يستورد نفس الملف مرتين، ولا يكرر أي سطر سبق استيراده حتى لو أتى بملف مختلف).
5. بإمكانك أيضاً كأدمن الضغط على "🔄 فحص المجلدات الآن يدوياً" داخل النظام بدل انتظار إعادة النشر، إذا كان السيرفر شغّال ولم يُعَد نشره بعد.

## 6) الدخول الأول
افتح رابط التطبيق الذي يعطيه Railway (Settings → Networking → Generate Domain)، وسجّل دخول بـ `ADMIN_USERNAME`/`ADMIN_PASSWORD` اللي ضبطتهم. من شاشة المستخدمين أنشئ حسابات المندوبين — **مهم:** اسم المندوب بحساب المستخدم يجب أن يطابق تماماً نص عمود "مندوب المبيعات" بملفات الاستيراد حتى يشوف كل مندوب عملاءه فقط.

## ملاحظات
- كل بيانات المسحوبات والتوقعات تُخزَّن بقاعدة PostgreSQL (دائمة، ما بتنمسح مع كل نشر جديد). الملفات نفسها (CSV) تبقى بالمستودع كسجل تاريخي، ويمكن حذفها لاحقاً من الريبو بدون أي أثر على البيانات المستوردة فعلياً بقاعدة البيانات.
- لاحقاً عند ربط مباشر بـ SAP Business One (HANA)، تُستبدل خطوة "الملف عبر GitHub" باتصال آلي يسحب الفروقات فقط — بقية النظام (محرك التوقع، الشاشات) لا يتغير.
